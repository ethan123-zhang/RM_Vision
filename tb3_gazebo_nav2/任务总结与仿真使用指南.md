# TB3 + Nav2 仿真：任务总结与使用指南

## 1. 一句话结论

在 WSL2(Ubuntu-24.04) 上用 **ROS 2 Jazzy + Gazebo Harmonic** 跑通了 **Nav2 官方 TurtleBot3 示例**：
导航闭环正常（`/navigate_to_pose` 返回 `SUCCEEDED`、无恢复动作、RTF≈0.90），
**但图形栈没有 GPU 加速**（llvmpipe 软渲染），这是当前 WSL 内核缺 DRM 导致的，与显卡无关。

## 3. 图形加速：结论、证据、修复路径

**结论：WSL2 支持 GPU 图形加速，本机显卡也够格；但当前 WSL 内核没有 DRM 子系统，所以只能用 CPU 软渲染。**

关键证据链：

| 判据                                  | 实测                                                                                                          |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `/dev/dri`（应有 `card0`、`renderD128`） | ❌ 不存在                                                                                                       |
| `/proc/devices` 里的 `226 drm`        | ❌ 没有 → DRM 核心未编入内核                                                                                          |
| `dmesg` 中 drm 相关日志                  | ❌ 0 条                                                                                                       |
| 内核日志                                | `PAT support disabled because CONFIG_X86_PAT is disabled`（官方 WSL 内核不会关 PAT）                                 |
| 计算通道                                | ✅ `/dev/dxg` 存在、`nvidia-smi -L` 正常 → GPU 半虚拟化算路通                                                            |
| 工具实测                                | `glxinfo -B` → `llvmpipe`、`Accelerated: no`；`vulkaninfo` → `lavapipe`                                       |
| WSLg 交叉印证                           | `Xwayland glamor: GBM Wayland interfaces not available` / `Failed to initialize glamor, falling back to sw` |

因果链：**内核无 DRM → 无 `/dev/dri` → Mesa 的 `d3d12_dri.so` 无处绑定 → 回落 llvmpipe**。
计算走独立的 `/dev/dxg`，所以「能算不能画」。

修复路径（判据唯一：`ls /dev/dri` 有节点 + `glxinfo -B` 显示 `Accelerated: yes`）：

```powershell
wsl --update
wsl --shutdown
wsl -d Ubuntu-24.04 -e bash -c "ls -l /dev/dri; glxinfo -B | grep -E 'renderer|Accelerated'"
```

- 出现节点 → 之后 Gazebo/RViz 自动走 d3d12，帧率数量级提升。
- 仍无节点 → 内核是被替换过的精简构建，需重装 WSL 包；改 Mesa 版本、装 Vulkan ICD 一律无效。
- 不影响 `/dev/dri` 但要知道：本机桌面由向日葵 Oray + GameViewer 虚拟显示驱动支撑（`IsVirtualMonitorsInstalled=1`），恢复加速后远程串流帧率仍受编码/带宽限制。

## 4. 遇到的问题与解法（按重要性排序）

| #   | 问题                             | 现象                                                                                                                                                                                                    | 根因                                           | 解法                                                                                        |
| --- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1   | **AMCL 没有初始位姿导致整个 bringup 中止** | 日志先刷 `Timed out waiting for transform from base_link to map`，再 `Failed to change state for node: planner_server`、`Aborting bringup`；`planner_server/bt_navigator/behavior_server` 停在 `inactive`，导航不可用 | 没有初始位姿 → AMCL 不发 `map→odom` → 全局代价地图永远等不到 TF | 等价 RViz 的 "2D Pose Estimate"，用话题发（spawn 点 `(-2.0,-0.5)`），发完 1 s 内 TF 出现；已固化进 `bringup.sh` |
| 2   | 默认发行版不是 Ubuntu                 | `wsl -e bash` 报 `execvpe(bash) failed`                                                                                                                                                                | 默认是 `docker-desktop`                         | 所有命令显式 `-d Ubuntu-24.04`                                                                  |
| 3   | `sudo` 要密码                     | `sudo: a password is required`                                                                                                                                                                        | 未配置免密                                        | 用 `wsl -u root` 执行 apt                                                                    |
| 4   | `set -u` 让脚本直接退出               | `AMENT_TRACE_SETUP_FILES: unbound variable`                                                                                                                                                           | ROS 的 `setup.bash` 引用未定义变量                   | `source` 前 `set +u`（`run_nav2_tb3.sh` 已改）                                                 |
| 5   | 图形无加速                          | 上面第 3 节                                                                                                                                                                                               | WSL 内核缺 DRM                                  | 暂用软渲染（够用）；修复见第 3 节                                                                        |
| 6   | DSH 沙箱挡住 `wsl.exe`             | `Wsl/E_ACCESSDENIED`                                                                                                                                                                                  | 沙箱内打不开 WSL 服务的命名管道                           | 调用 wsl 时提权到 `danger-full-access`                                                          |
| 7   | 按 X 窗口抓图不可靠                    | `import -window` 前后差异仅 0.02%                                                                                                                                                                          | WSLg 下 GL 直出，X 侧抓到近似冻结帧                      | 取证改用 Windows 整屏抓取（`grab.ps1`），并用跨时刻帧差证明在刷新                                                |
| 8   | PowerShell 吃掉 bash 变量          | `find: ' -maxdepth': No such file…`、命令静默变空                                                                                                                                                            | `$var`/`$(...)` 被 PowerShell 先展开             | 逻辑一律写进 `.sh` 文件再执行；新写的 `.sh` 先 `sed -i 's/\r$//'`                                         |
| 9   | WSL 的 localhost 转发被关           | `wsl: 无法配置 localhost 转发到 WSL`                                                                                                                                                                         | NAT 模式                                       | Windows 侧访问 WSL 端口用 WSL IP 或镜像网络；全在 WSL 内操作则无影响                                           |

## 5. 这套仿真里"谁跟谁配合"

```
   ┌─────────────── Gazebo Sim（仿真世界）───────────────┐
   │  gz sim -s  服务器：物理引擎、传感器（激光/相机）、时钟 │
   │  gz sim -g  客户端：3D 画面（可关，headless）          │
   └───────────────┬──────────────────────────────────────┘
                   │ gz 话题（gz-transport）
          ┌────────▼─────────┐
          │  ros_gz_bridge    │  按 bridge yaml 双向搬运
          └────────┬─────────┘
                   │ ROS 2 话题：/clock /scan /odom /cmd_vel /tf
   ┌───────────────▼───────────────────────────────────────────┐
   │ Nav2 导航栈（composable 容器内多节点）                       │
   │  map_server → AMCL（定位）→ planner_server（全局规划）       │
   │  → controller_server（局部控制, DWB）→ /cmd_vel             │
   │  bt_navigator 用行为树串起上面这些；costmap 出代价地图        │
   └───────────────┬───────────────────────────────────────────┘
                   │ TF：map → odom → base_link → laser/camera
          ┌────────▼─────────┐
          │  RViz2            │  看 + 点：2D Pose Estimate / Nav2 Goal
          └──────────────────┘
```

| 软件                        | 角色                      | 你什么时候会碰它           |
| ------------------------- | ----------------------- | ------------------ |
| **Gazebo Sim**（`gz sim`）  | 物理世界、传感器、仿真时钟           | 建模场地/放机器人/看画面      |
| **ros_gz_bridge**         | Gazebo ↔ ROS 2 的话题与时钟桥接 | 加新传感器时要改 bridge 配置 |
| **robot_state_publisher** | URDF → TF 静态坐标系         | 换机器人模型时            |
| **Nav2**                  | 地图加载、定位（AMCL）、规划、控制、行为树 | 调参数、发导航目标          |
| **RViz2**                 | 可视化 + 交互主界面             | 日常操作都在这里           |
| 可选：**slam_toolbox**       | 建 2D 地图                 | 做 RM3V3 地图时用得上     |
| 可选：**rqt / ros2 bag**     | 调试、录包回放                 | 排查/复现问题            |

**核心概念（4 个就够用）**

- `use_sim_time=true`：所有节点用 `/clock` 的仿真时间，不是墙上时间。看时间对不对：`ros2 topic hz /clock`。
- **TF 树**：`map → odom → base_link`。`odom→base_link` 由轮速/里程计给；`map→odom` 由 AMCL 给（所以没初始位姿就没有它）。
- **costmap**：把 `/scan` 与地图揉成"哪里不能走"。RViz 里红蓝点云就是它。
- **行为树**：Nav2 用 BT 编排"算路→跟随→卡住就恢复"。`bt_navigator` 是入口。

## 6. 日常怎么用

### 6.1 起停

```bash
# 起（清场 → 启动 → 发初始位姿 → 等导航栈 active）
wsl -d Ubuntu-24.04 -e bash -c "bash /mnt/e/RM/tb3_gazebo_nav2/bringup.sh"
# 停
wsl -d Ubuntu-24.04 -e bash -c "bash /mnt/e/RM/tb3_gazebo_nav2/stop.sh"
# 看状态（话题频率/生命周期/TF/CPU）
wsl -d Ubuntu-24.04 -e bash -c "bash /mnt/e/RM/tb3_gazebo_nav2/verify.sh"
```

### 6.2 五个必会操作

| 想做的事     | 做法                                                             |             |
| -------- | -------------------------------------------------------------- | ----------- |
| 让机器人去某点  | RViz 点 **Nav2 Goal**，或 `bash nav_goal.sh 1.0 -0.5`             |             |
| 重新定位     | RViz 点 **2D Pose Estimate** 拖出朝向（等价发 `/initialpose`）           |             |
| 键盘遥控     | `ros2 run turtlebot3_teleop teleop_keyboard`（终端里按 WASD）        |             |
| 看话题有没有数据 | `ros2 topic list`；**注意话题存在 ≠ 有数据**，要 `ros2 topic hz /scan`     |             |
| 确认导航栈活着  | `ros2 lifecycle get /bt_navigator` 应为 `active`；`ros2 node list | wc -l` 约 30 |

### 6.3 命令速查（每条都要先 `source /opt/ros/jazzy/setup.bash` + `export ROS_DOMAIN_ID=42`）

```bash
ros2 pkg list | grep nav2                 # 装了哪些 nav2 包
ros2 node list                            # 有哪些节点
ros2 topic list / hz / echo <t> --once    # 话题
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{...}" --feedback
ros2 lifecycle get /amcl                  # 生命周期状态
gz topic -l                               # Gazebo 侧话题
gz sim --versions                         # Gazebo 版本
ros2 run rviz2 rviz2 -d <config.rviz>     # 单独开 RViz
```

### 6.4 常见症状 → 先查什么

| 症状 | 先查 |
| --- | --- |
| RViz 里 TF 报红、costmap 空 | `map→odom` 有没有：发 `/initialpose` |
| 导航一直不开始、目标立刻失败 | `ros2 lifecycle get /planner_server` 是否 active（inactive 就是 bringup 中止了） |
| RViz 里机器人不动但 `/odom` 在变 | RViz 的 Fixed Frame 是不是 `map`，有没有加 TF/Scan 显示 |
| 一切都很慢 | 软渲染所致；关 Gazebo GUI（`headless:=True`）、缩窗口、关 RViz 会明显好转 |
| Gazebo 起不来/黑屏 | `logs/nav2_tb3_gui.log` 末尾；再查 `gz sim --versions` 与 `DISPLAY` |

## 7. 有没有中文版？

**结论：Gazebo / RViz2 / Nav2 都没有官方中文界面，也没有可切换的语言选项。**

- Gazebo（含 Harmonic 的 GUI）、RViz2、Nav2 的所有报错、面板、日志都是英文；它们不提供 i18n 语言包，找不到"中文版"这个开关。
- 能"中文化"的只有**你自己的东西**：RViz 配置里的显示项名字、自定义 launch/参数文件里的注释、自己写的节点日志。
- 实用替代：
  1. 中文教程生态很成熟（B 站/知乎/古月居/鱼香ROS），看不懂的术语搜"XX 中文"通常立刻有答案；
  2. 看官方文档时优先看 **Nav2 官方文档的 `Getting Started`**，图和命令比文字重要；
  3. 如果目标是 **RoboMaster 场地仿真**：DJI 有官方的 **RoboMaster 机甲大师模拟器**（中文界面），但那是封闭的比赛环境，接不了 Nav2/自定义算法栈；你现在这套 Gazebo+Nav2 是开放栈，两者不是一条路线。

**术语中英对照（够用版）**

| 英文 | 中文 | 英文 | 中文 |
| --- | --- | --- | --- |
| world | 世界/场景 | costmap | 代价地图 |
| model / link / joint | 模型/连杆/关节 | global/local planner | 全局/局部规划器 |
| plugin | 插件 | controller | 控制器（输出速度） |
| sensor / topic | 传感器/话题 | behavior tree (BT) | 行为树 |
| frame / TF | 坐标系/坐标变换 | recovery | 恢复行为 |
| odom / scan | 里程计/激光扫描 | lifecycle | 生命周期（未激活就没干活） |
| spawn | 生成（把机器人放进世界） | goal / waypoint | 目标点/航点 |

## 8. 下一步：RM3V3 地图导入（大致路线）

### 8.1 先分清两张"地图"——这是最容易混的地方

| | Gazebo 世界（仿真用） | Nav2 地图（导航用） |
| --- | --- | --- |
| 文件 | `.sdf` / `.world`（xacro 可生成） | `.pgm` + `.yaml` |
| 内容 | 3D 几何 + 材质 + 碰撞 + 物理 + 光照 | 2D 黑白栅格 + 分辨率/原点 |
| 谁读 | `gz sim -s` | `map_server` |
| 作用 | 让"假世界"里能跑物理和传感器 | 让 AMCL/规划知道哪里能走 |

**两者必须尺寸、原点、朝向一致**，否则定位对不上。RM3V3 场地要**两边都做**。

### 8.2 推荐流程（5 步）

1. **拿场地素材**：官方场地尺寸图（俯视 CAD 或带标注的平面图）、障碍物/坡道/围挡位置、机器人实际尺寸与最大速度。
2. **建 Gazebo 世界**：按尺寸在 Blender/SketchUp/Onshape 建模 → 导出 DAE → 写 `worlds/rm3v3.sdf`；场地静态部分用简单碰撞体（Box/Plane）即可，别用高面数网格做碰撞。
3. **建 Nav2 地图，二选一**：
   - **省事**：在 Gazebo 里跑 `slam_toolbox` 扫一圈，`ros2 run nav2_map_server map_saver_cli -f rm3v3` 直接出 `pgm+yaml`；
   - **精确**：按图纸比例在 GIMP/PS 里画黑白图（黑=占用，白=空闲），手写 yaml（`resolution: 0.05`、`origin: [x, y, 0]`）。
4. **接机器人**：换成 RM 的 URDF/xacro；麦轮底盘需要对应的运动学插件（Gazebo 侧 `gz::sim::systems::DiffDrive` 不适用时用 `MecanumDrive`/自定义），Nav2 侧仍用速度指令接口。
5. **跑闭环**：`map_server` 加载新地图 → AMCL 初始位姿 → 发目标 → 看 costmap 是否与场地吻合 → 调 `nav2_params.yaml`（膨胀半径、速度、控制器频率）。

### 8.3 放文件的位置与找资源的规则

- 世界：`<你的包>/worlds/*.sdf`；模型：`<你的包>/models/<model>/model.config` + `model.sdf`。
- Gazebo 靠环境变量找 `model://`：`export GZ_SIM_RESOURCE_PATH=<你的包>/models:<其他>`（ROS 包会在 `setup.bash` 里自动加）。
- Nav2 地图：`<你的包>/maps/rm3v3.yaml` + `rm3v3.pgm`，launch 里 `map:=` 指过去。
- 参数：复制 `nav2_bringup/params/nav2_params.yaml` 改成自己的，别改系统里那份。

### 8.4 三个容易踩的坑

1. **单位和原点**：SDF 用米，地图 `resolution` 是"米/像素"，`origin` 是图像左下角在世界中的坐标；三者错一个点，AMCL 就永远定不上位。
2. **碰撞体别用视觉网格**：直接拿 DAE 当碰撞体，物理会卡死或穿模；用简化 box/cylinder。
3. **别改 `/opt/ros` 里的系统文件**：所有世界/地图/参数都放自己的工作空间，launch 里引用绝对路径或通过包名解析。

## 10. 现场状态与恢复

- **当前状态：已停止**。2026-11-01 17:50 左右整套 launch 收到 SIGINT 后正常关闭
  （日志末尾 `LifecycleManager rcl preshutdown` → `component_container` 超时被 SIGKILL，是正常退出路径）；
  **WSL 本身没有重启**（`uptime` 连续），只是仿真进程组的生命周期结束了。
- 重启一条命令（约 40 秒到导航栈 active，Gazebo Sim + RViz 窗口会自动出现在 WSLg 里）：

```bash
wsl -d Ubuntu-24.04 -e bash -c "bash /mnt/e/RM/tb3_gazebo_nav2/bringup.sh"
```

- 再停：`bash stop.sh`（一条命令）。
- 注意：**关掉 Gazebo/RViz 窗口或按 Ctrl+C，整套 launch 会跟着退出**——这是预期行为，
  不是崩了；重跑 `bringup.sh` 即可。
- 换地图的起点：先把 RM3V3 的 `worlds/*.sdf` 与 `maps/*.pgm|yaml` 做出来，再把 `bringup.sh` 里的 `world:=` 与 `map:=` 指过去。

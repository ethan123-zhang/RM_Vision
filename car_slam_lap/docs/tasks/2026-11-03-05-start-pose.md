# 任务05：起始姿态控制（回起点＋起始对齐）

实车首测（2026-11-03 22:03，见 `docs/experiments/2026-11-03-car-ros-control/README.md`）证明：现有"回起点→起始对齐"流程在这台车上不可能满足原判据，原因是物理的，不是参数没调好。

## 已确认的事实（实车测量）

- 位姿传感器（Odin1 imu，即 `base_frame`）**偏离车体转心约 0.25 m**。证据：纯原地转 77° 期间位姿点扫过 0.316 m；两次独立测量（角速度标定 0.19–0.22 m、回放 0.25 m）一致。
- 因此"位姿点在起点 ± `start_pos_tol_m`"与"朝向对齐到起点朝向"**互斥**：对齐 140° 的朝向差必然让位姿点平移 2×0.25×sin70° ≈ 0.47 m。
- 另一独立缺陷（已修）：回起点"边走边转"时 `w=1.5*heading_err` 配低速，转弯半径只有 0.14 m < 到位容差 0.10 m，追踪一个点会退化成绕点打圈。现已用 `RETURN_MIN_RADIUS_M=0.40` 对行驶中的角速度封顶。
- 已修但不够（`START_ALIGN_DRIFT_SLACK_M=0.15`）：只是把漂移阈值从 0.10 抬到 0.25，仍小于 0.47 m。

## 必须二选一（用户未定，默认不做）

> **2026-11-04 更新：用户选定 B，已实现并通过单元测试；但仿真证明 B 单独不能满足自己的验收用例。见本节末尾"实现结果"。**

### A 宽松起点（改动最小，先解锁跟踪验证）

- 判据改为"位姿点距起点 ≤ `start_pos_tol_m` 且朝向差 ≤ `start_yaw_tol_rad`"，运行时取 0.50 m / 0.60 rad（34°），漂移判据随之允许 0.65。
- 语义变化：不再保证"从准确起点姿态出发"，由纯追踪在头 1 m 内自行收敛。
- 必须写清楚：这是**降级**，默认值保持严格；只作为参数组合使用，并在启动日志里显著提示。
- 验收：车在起点 0.5 m 内、朝向差 34° 时能进入 `run`，且头 1 m 内横向误差收敛到 ≤5 cm。

### B 先转正再补位置（保留严格保证，工作量更大）

- `align_start` 只负责朝向：转到 `|yaw_err| ≤ start_yaw_tol_rad` 期间**不做位置判据**。
- 转正后若 `dist > start_pos_tol_m`，回到 `return` 重新靠近（此时朝向已对，只剩平移）；`return` 到位后再进 `align_start`，朝向通常已达标→`run`。
- 需要防抖：限制往返次数（例如 ≤3），共享 `return_timeout_s` 兜底；每次往返必须记录日志；超次数按失败停车。
- 要注意 `return` 行驶时仍会小角度修正朝向，可能又引入几度偏差，因此每轮漂移应递减——若实测不收敛，回到 A。
- 验收用例：位姿点在起点 0.5 m、朝向差 140° 时，能通过 ≤3 轮完成"转正+补位"，最终 `dist ≤ start_pos_tol_m` 且 `|yaw_err| ≤ start_yaw_tol_rad` 后进入 `run`；超时/超轮次失败停车且全程只前进。

## 实现结果（2026-11-04，方案 B）

已实现（`follow_path.py`，测试 `test_follow_safety.py`）：

- `align_start` 只判朝向，转动期间不再有位置判据（删掉 `START_ALIGN_DRIFT_SLACK_M` 与"漂离首点"判死）。
- 朝向达标后再看位置：`dist > start_pos_tol_m` 就回 `return` 补位，计一轮。
- 往返上限 `START_RETURN_ROUNDTRIP_MAX = 3`，超限失败停车；总超时仍走共享的 `return_timeout_s`；每轮 info 日志；`summary` 增加"补位往返 N 次"。
- 行为测试覆盖：对齐期间不判位置、朝向达标但位置差回 return、一轮收敛进 run、超轮次失败停车且写零、全程只前进或原地转。

**仿真结论（用差速车运动学 + 传感器偏置复现实车几何，r = 0.25 m）**：

| 场景 | 结果 |
| :--- | :--- |
| r = 0，0.45 m / 140° | ✅ 3 轮内收敛进 `run`（状态机本身正确） |
| r = 0.25 m，严格判据（0.10 m / 5.7°），0.45 m / 140° | ❌ 极限环：dist 在 0.099↔0.137 m 往复，第 4 轮安全停车 |
| r = 0.25 m，方案 A 参数（0.50 m / 34°），0.45 m / 30° | ✅ 直接进 `run`（允许转角小到等效平移仍在容差内） |

极限环机理：`align_start` 要把朝向转回路线起点方向，而 `return` 要把车头对准目标点，两者在这套几何下互相抵消；每转一圈传感器点被力臂带着平移，位置永远差 0.03–0.04 m。

**因此**：B 的验收用例（0.5 m / 140° 严格起点）在力臂存在时不成立，B 只能保证"失败得安全"。给出三条路，等用户定：

1. **A 宽松起点**（推荐先用）：纯参数组合 `start_pos_tol_m:=0.50 start_yaw_tol_rad:=0.60`，同一几何仿真已验证可进 `run`，后续靠纯追踪收敛（2026-10-26 实车 rms 0.103 m 说明跟踪本身能带这个力臂跑）。
2. **C 力臂补偿**（正解）：给节点加 `base_offset_x/y`（传感器相对转心），把判据和回起点目标换成"转心位姿"；旋转不再改变转心位置，B 的往返循环自然消失。代价：需要在车上标定 offset 的符号与数值（原地转 90° 看位姿点移动方向即可）。
3. 保持 B 严格判据直接上车：预期仍在 `align_start` 判停，只用于再次取证，不建议。

## 实现结果（2026-11-04，方案 C 力臂补偿）

用户选 C 后已实现并验证：

- 新增参数 `base_offset_x` / `base_offset_y`（m，车体系，默认 0）：约定
  `传感器位姿 = 转心 + R(yaw)·offset`。默认 0 时行为与 B 完全一致。
- 新增 `_rotation_center()`：把 `base_frame` 位姿换算成转心位姿；力臂为零时原样返回，不引入浮点噪声。
- 起点范围检查、`return` 的目标点与 `align_start` 的位置判据全部改用**转心**：
  原地转只让传感器点绕转心画圆，转心不动，"转正"和"到位"不再互斥。
- B 的补位往返逻辑保留，作为"未配补偿 offset 或 offset 标错"时的安全兜底。
- 标定公式：原地转 180°，记位姿点位移 `Δs` 与转前朝向 `yaw0`，
  `offset = -R(-yaw0)·Δs / 2`（README §14.3 有步骤）。

**测试与仿真（r = 0.25 m，0.45 m / 140°，严格判据 0.10 m / 5.7°）**：

| 配置 | 结果 |
| :--- | :--- |
| 不补偿（B） | ❌ 极限环，第 4 轮安全停车 |
| `base_offset_x=0.25`（C） | ✅ 一次进 `run`，**补位往返 0 次**，总耗时 < 30 s |

本地 **169 项测试全过**（其中安全测试 79 项，含 6 项 C 专属：参数校验、默认零、
偏置随朝向旋转、目标点是补偿后的转心、传感器压在起点但转心偏了不算到位、整段仿真收敛）。

   `_rotation_center` 改终点判据——需单独立项与验收。

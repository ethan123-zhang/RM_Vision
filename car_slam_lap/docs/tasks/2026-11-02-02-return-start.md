## 【输入输出定义】

在follow_path中增加参数：
- return_to_start=True；False仅用于已人工对齐的诊断模式，必须警告。
- start_max_offset_m=0.5：第一帧有效地图位姿距首点超过此距离，零输出并失败。
- start_pos_tol_m=0.10、start_yaw_tol_rad=0.10。
- return_v_max=0.08、return_w_max=0.4、return_timeout_s=30.0。

上述是保守的软件初始配置，不是硬件已验收范围。所有参数必须是有限正数（速度允许0以支持静止诊断），非法参数初始化时拒绝。

默认执行顺序为启动宽限零输出 -> 在原有定位/底盘安全门通过后检查起点范围 -> return_start -> align_start -> run -> align_final -> done。为了避免破坏原有47项用例，可在原测试helper中明确关闭return_to_start，仅测试旧跟踪安全行为；新增专门测试覆盖默认的回起点流程，不能通过全局默认False绕过新功能。

回起点阶段只允许在已确认空旷的小范围执行，不实现自动绕障或任意地点返回。起点目标使用路线首点的x/y/yaw；帧为地图坐标。历史odom诊断只能return_to_start=False，否则拒绝。

位置接近控制使用车体前进方向：先计算到首点的方位角并 wrap_pi；偏差大于0.35rad先原地转向，线速度0；偏差小则正向低速接近，不倒车，距离越近线速度越小，角速度限幅。到首点位置容差内先发零，进入align_start；按最短角差原地对齐yaw。若对齐期间漂出位置容差，零输出并失败。

回起点与起始对齐使用同一个monotonic总超时。时间到、原始里程计停更、非法位姿、TF丢失、底盘异常等沿用任务01失败停车，不得跳过或自动恢复。

只有起点位置和朝向都达标后才能进入run。切换时重置路线idx=0、跟踪累计里程/上一位姿/终点对齐计时，回起点走过的距离不得计入路线完成进度。实际轨迹日志可以包含回起点阶段，但summary区分回起点与路线跟踪时间/结果即可，不加庞大日志框架。

已有纯追踪180度掉头和复杂交叉仍待后续实测改进，本任务不要承诺完成绕障或任意路线。

## 【核心算法逻辑伪代码】

```text
安全门通过且首次有map位姿:
    超出返回范围 -> 失败停车
    return_start
return_start:
    超时 -> 失败
    距首点 <= tol -> 零输出，align_start
    方位误差大 -> 原地转
    否则 -> 限速接近首点
align_start:
    位置漂离/超时 -> 失败
    yaw达标 -> 零输出，重置路线进度，从首段开始run
    否则 -> 限速原地转
```

## 【异常与边界条件】

起点就在闭合路线终点附近也必须从首段开始；返回不能就近插入中段。起始yaw相差接近pi时仍使用最短角方向，不发前进速度。所有状态持续经过任务01安全门。状态转换时不得发布上一状态遗留速度。不得用定位跳变的累计里程绕过首次返回范围限制。

## 【验收测试用例】

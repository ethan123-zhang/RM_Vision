# 讲解：车一原地转就偏——力臂、转心与"到没到"的判据

> 这份文档解释 2026-11-04 晚排练中三个"莫名其妙"的失败，以及它们共同的几何根因。
> 先直觉、后公式；关键术语第一次出现就解释，后文再点回来。

---

## 0. 要回答的问题

车在终点附近连续报三个失败：

| 日志 | 字面意思 |
| :--- | :--- |
| `最终对齐时已漂离终点 0.22 m > goal_tol=0.20 m` | 原地转向时"位置漂走了" |
| `大转角原地对齐超时（15.0 s）` | 原地转很久也到不了 |
| `最终朝向对齐超时（失败，未走完）` | 朝向前就差一点 |

车其实一直"在正确执行指令"。问题不在开得准不准，而在**我们判"到没到"的方法本身**。

## 1. 直觉：雨刷器和手电筒

伸出一只手拿手电筒，**原地转身**。你的脊柱（转轴）没动，手电筒却画了一个圆。

这时如果有人要求你："手电筒必须停在墙上那个点，同时你的身体必须朝某个方向"——你会立刻发现这两件事互相打架：身体一转，手电筒必然离开那个点。

**角色对应**：

- 脊柱 = 车体**转心**（车原地转时唯一不动的那个点）
- 手电筒 = **Odin1 雷达**，也即轨迹位姿的来源（`base_frame=imu`）
- 手臂长度 = **力臂 offset**（雷达相对转心的固定偏置，约 0.26 m）

**边界**：这个类比成立的前提是手臂刚性绑在身上、长度不变。真实系统里雷达用螺丝固定在车上，力臂确实固定——所以这个模型是准的；但如果有一天改了雷达安装位置，手臂长度就变了，必须重新标定（见 §3.4）。

## 2. 机制：车怎么转、雷达怎么动

### 2.1 "原地转"是什么

本车是两轮差速底盘：`/cmd_vel` 里的 `linear.x`（v）和 `angular.z`（w）经 `bridge_node` 按 `mps_at_max`/`radps_at_max` 换算成 ±1000 指令单位，串口发给 C8T6，再走 CAN 给控制器。

当 `v=0, w≠0` 时，左右轮同速反向转，车绕**车体中心附近的某点**旋转。这个点就是**转心**：原地转时它不动，其余所有点都在绕它画圆。

### 2.2 雷达位姿 = 转心 + 旋转后的力臂

把"雷达在车体系里的位置"记作 `offset = (ox, oy)`（本车标定值 `+0.2626, −0.0471`，模长 0.267 m，大致是车头前方的偏左一点）。车朝向为 `yaw` 时，雷达在场地里的位置是：

```
传感器位姿 = 转心 + R(yaw)·(ox, oy)
```

`R(yaw)` 是二维旋转矩阵：把车体系里的向量转到世界系。**关键在于 yaw 一变，这一项就变**——即使转心纹丝不动。

### 2.3 用数字感受一下

原地转 Δψ 角，雷达点沿圆周移动的距离是弦长：

```
位移 = 2·|offset|·sin(Δψ/2)
```

- 转 90°：`2 × 0.267 × sin45° ≈ 0.38 m`
- 转 155°：`2 × 0.267 × sin77.5° ≈ 0.52 m`
- 转 180°：`2 × 0.267 ≈ 0.53 m`

**实测校验**：标定那次车转了 169.9°（半角 84.95°），雷达点位移实测 0.531 m，理论 `2×0.267×sin84.95° ≈ 0.532 m`。**测量与模型一致**，所以这不是"调参能压小的误差"，是几何事实。

### 2.4 为什么"位置到位"和"朝向对齐"会打架

早期（11-03）的失败是这条因果链的直接后果：判据要求"雷达点距起点 ≤ 0.10 m **且** 朝向误差 ≤ 0.10 rad"。可朝向差 140° 时，为了让朝向对齐必须原地转 140°，雷达点就必然平移约 0.47 m——两个条件不可能同时满足。控制器于是在"转正"和"补位"之间来回，绕圈 194° 才蹭进容差圈，朝向还是错的。

**这是设计缺陷，不是调参问题**：你怎么调容差或增益，几何约束都还在。

### 2.5 反过来用：力臂可以反解（标定）

已知"转前后雷达位姿"，就能解出力臂。把转前转后记作 `s0, s1`，朝向 `y0, y1`：

```
s1 − s0 = R(y1)·offset − R(y0)·offset
```

若转的是 180°（`y1 = y0 + π`），右边化简为 `−2·R(y0)·offset`，于是：

```
offset = −R(−y0)·(s1 − s0) / 2
```

本车 `ros2 run car_bridge calibrate_lever_arm` 就是"静止起点 → 原地转够 120° → 停稳 1 s → 用上式反解"，输出 `-p base_offset_x/y:=...`。模长 >0.6 m 或 <0.02 m 会告警，因为那通常意味着车不是原地转、被拖着走了，或定位跳变。

## 3. 解法：把判据换算到转心

既然雷达点会绕转心画圆、而转心原地不动，**所有"到没到"的判断都应该看转心**：

```
转心 = 传感器位姿 − R(yaw)·offset
```

（实现：`follow_path._rotation_center()`；offset 为 0 时它原样返回，旧行为不变。）

这样改完有三层效果：

1. **原地转正期间位置判据稳定**——转心不动，不会出现"越转越偏"的误判；
2. **朝向一对齐，雷达点自动落回示教点**——因为示教点就是"该朝向下的雷达位置"，两者由同一个公式联系；
3. **起点、回起点、终点、末段用的是同一套坐标**，不会再出现"起点用转心、终点用传感器点"的割裂。

三处改造（提交 `867a400`）：

| 位置 | 改造前 | 改造后 |
| :--- | :--- | :--- |
| 起点范围检查 / 回起点目标（任务 05 方案 C） | 传感器点 | 转心 |
| 最终对齐 `align` 的位置判据 | 传感器点 → 转 155° 被判"漂离 0.22 m" | 转心 |
| 末段收口的目标点 | 路线最后一个点 | 终点转心 |

## 4. 三个终点缺陷，逐个说清

### 4.1 缺陷一：原地转正被自己的力臂"判犯规"

`align` 状态（最终原地转正）里有一句检查："离终点超过 `goal_tol` 就判失败"。它原来比的是雷达点。路线末段的朝向差是 155°，车一转头，雷达点从终点扫出去 0.52 m——检查立刻报 `已漂离终点 0.22 m`。

改成看转心后，转正期间转心不动，检查通过；转完朝向对齐，雷达点正好回到示教位置。现场复验：同样的 155° 场景从"失败"变成"成功"，朝向误差 0.09 rad。

### 4.2 缺陷二：末段"原地打转"——纯追踪在单点目标上会绕圈

**先解释纯追踪**：它不给车排一条完整轨迹，而是每帧取路线上一段"前视点"（默认 0.35–0.8 m 以外的一个点），算出方位差 `α`，用曲率 `κ = 2·sin(α)/d`（d 是到该点的距离）换算成角速度 `w = v·κ`。它的好处是天然平滑，坏处是——**它假设目标"在路线上、前方、有距离"**。

到了末段，这三个假设全破了：

1. 示教时我停下车说话，录制器还在采点，**最后 3 个点间距只有 0.2 mm**（几乎重合）。拿它当前视点，方位角 `α` 完全被噪声支配，`w` 左右乱摆。
2. 更要命的是纯追踪的几何：目标点是固定的，当 `α` 和 `d` 稳定下来，`κ` 也稳定 → 车走一个半径 `R = 1/κ = d/(2 sin α)` 的圆弧，**正好绕着目标转圈**。实测 `d` 卡在 0.33 m、`w` 恒定 0.57 rad/s，永远进不了 0.20 m 的容差圈；转 15 s 后触发 `track_align` 超时。

**修法：末段换一种控制器（收口律）**——不追求"贴着线走"，只要"停得准"：

```
末段（剩余弧长 < 0.5 m 且真的走过半程）：
  若 方位差 > 0.35 rad → v=0，原地转（w 限幅）
  否则 → v = min(v_max, 0.12)，用一个小的前馈角速度修正
```

也就是"先对准，再直行"。同时补了一个坑：**"末段"的判据不能只看剩余弧长**。因为这是闭合路线，起点离终点只有 8 cm，只看弧长的话车一进 `run` 就会以为"到终点了"。所以要求"剩余弧长小 **且** 实际行驶里程 ≥ 全程一半"（`_min_goal_travel`）。

### 4.3 缺陷三：固定 5 秒的对齐超时

最后一步是原地把朝向转到与示教一致。`w_max=0.35 rad/s` 时转 176° 需要 `3.07 / 0.35 ≈ 8.8 s`，而超时固定写死 5 s——**物理上转不完**，必然报"对齐超时"。

修法：超时按初始角度估算，`max(5 s, 1.5·|Δyaw| / (0.8·w_max))`。176° 时给到约 16 s，留 1.5 倍余量；小角度仍是 5 s 兜底。

## 5. 另外三个工程问题（与力臂无关，但同样让演示卡住）

1. **转弯太猛**：`follow_path` 的 `w_max` 内建默认 **1.2 rad/s ≈ 69°/s**，而 `drive_lap.sh` 只透传了 `v_max`。你看到的"转弯太快"就是它。现在 `drive_lap.sh` 透传 `W_MAX=0.35`、`RETURN_W_MAX=0.30`，并在启动横幅里回显生效值。
2. **参数类型崩**：ROS 2 按命令行字面量推断类型，`MAX_TIME_S=280` 被当成 INTEGER，而 `max_time_s` 声明是 DOUBLE → `InvalidParameterTypeException`，进程在动之前就退出了。脚本现在把所有数值统一补成浮点（`280` → `280.0`），非数字输入直接报错。
3. **示教中途被中止**：日志 `原始里程计停更 0.52 s`，同时 Odin1 驱动打 `Queue TF_ODOM is full, dropping oldest data`。这是主机侧回调队列溢出（CPU 调度抖动），不是雷达掉电——`lsusb` 还在、里程计自愈。处置：CPU 调频设 `performance`、关掉昂贵数据流，然后重录；**不要为了过检查去放宽时效阈值**，因为那段时间的位姿本身就是空的。

## 7. 可复用的四条规则

1. **先量力臂，再设计任何"到某位姿"的判据**：`r` 在 0.2–0.3 m 时，"位置±10 cm"与"朝向对齐"物理上不可同时满足。
2. **位置判据一律用转心**：`转心 = 传感器 − R(yaw)·offset`，只在 offset=0 时退化为传感器点。
3. **点目标不能用纯追踪**：它会给一个稳定的绕圈半径 `R = d/(2 sin α)`；近终点要换成"对准→直行"，并且末段判据要加"真的走过半程"。
4. **定时超时要随几何量缩放**：转 176° 的时间是 0.35 rad/s 下的 8.8 s，写死 5 s 就是必然失败。

## 8. 术语表（每个术语在流水线里的位置）

| 术语 | 是什么 | 在哪一步用 | 产出什么 |
| :--- | :--- | :--- | :--- |
| 转心 | 原地转时唯一不动的点 | 所有位置判据的坐标系 | 稳定的位置读数 |
| 力臂 offset | 雷达相对转心的固定偏置（车体系，m） | 位姿换算 `传感器 = 转心 + R·offset` | 转心坐标 |
| 前视点 | 路线上前方一段距离的参考点 | 纯追踪算曲率 | 目标方位角 α |

| 里程计新鲜度 | 原始 `/odin1/odometry` 时间戳是否在推进 | 每帧控制前 | 不新鲜就停车 |

## 9. 自查：你现在能解释开头那三个日志吗？

- "漂离终点 0.22 m"：因为判据看的是**雷达点**，而原地转 155° 让雷达点扫了 0.52 m；换成**转心**就稳定了。
- "原地打转超时"：纯追踪对固定点目标会稳定绕圈（`R = d/(2 sin α)`），加上末段重合尾点让方位角变噪声；改用**收口律**（对准→直行）。
- "朝向对齐超时"：`w_max=0.35` 下 176° 要 8.8 s，超时写死 5 s；改成**按角度自适应**。

三句话合起来是同一件事：**位姿来源带力臂，判据和控制器必须显式地把力臂算进去**。

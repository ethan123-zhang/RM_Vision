# 实时避障运行与验收

入口仍是“重定位 → 回起点与起始对齐 → 跟踪示教路线 → 终点收口与对齐”。
新增模块会根据运行时原始点云绕过地图中没有的静止障碍，实际到达接回点后继续原路线。
旧 `drive_lap.sh` 不加载避障参数时保持原有行为。

## 已部署的参数

`x5/config/obstacle_avoidance.yaml`：车长 0.65 m、宽 0.55 m、Odin1 高度 0.23 m；
车体暂按履带转心居中。车身外接圆加 0.10 m 余量，另留栅格与跟踪裕量，因此狭窄通道会偏保守地停车。
`robot_front_m` 是转心到最前端距离，默认 0.325 m；车头车尾不对称时需要实际测量后修改。
小角度运动只能帮助识别转心/自身回波，不能精确测出不可见外壳。
小角度标定与低速实车试验均须获得用户授权后执行。

原始点云实测水平覆盖约 129°，主要在前方。侧后方未观察区域的新障碍无法保证识别，
首次回起点与转向仍应在确认空旷的区域执行。规划中心不进入未观察格，但旋转的盲区不能靠软件补出传感器数据。

`odin1_self_mask.npz` 是本机经过小角度转动采样确认的三维自身回波掩码。
它只去除已标定的雷达坐标体素，不排除整个近距离扇区；新增箱体不能因为“离得近”而被全量忽略。
拆装雷达、更换车体或明显改变安装高度后应重新标定，并在没有新掩码前停止使用旧掩码。

## 运行

以下在 X5 执行；地图/路线使用现有配套 bundle，不需要因为后来增加一个箱子重新建图。

```bash
# 1. 重定位并开启实时原始点云；不启动底盘。
bash ~/car_slam_lap/x5/scripts/start_relocal_obstacles.sh ~/car_ws/maps/venue2-20261104

# 2. 静止感知检查：这个入口没有任何速度发布者。
source /opt/ros/humble/setup.bash
source ~/car_ws/install/setup.bash
ros2 run car_bridge obstacle_probe --ros-args \
  --params-file ~/car_ws/config/obstacle_avoidance.yaml

# 3. 起底盘桥接。发送零帧也会接管遥控，想用遥控须先停桥接。
ros2 run car_bridge bridge_node &

# 4. 确认场地允许运行后再执行；Ctrl-C 会发零并保存此次实际轨迹。
START_MAX_OFFSET_M=2.0 RETURN_TIMEOUT_S=150 MAX_TIME_S=320 \
bash ~/car_slam_lap/x5/scripts/drive_lap_obstacles.sh ~/car_ws/maps/venue2-20261104
```

避障运行默认速度上限 0.15 m/s，临时绕行上限 0.12 m/s，角速度 0.35 rad/s。
启动脚本沿用已有标定力臂 `(0.2626, -0.0471)` m，可通过原有环境变量覆盖。
实际轨迹写 `lap_actual_obstacles.yaml`，保留旧 `lap_actual.yaml` 基线。
有有效局部网格与控制位姿时，同时保存 `lap_actual_obstacles.yaml.obstacles.npz`；
其他实际轨迹路径也使用完整原路径加 `.obstacles.npz`。
快照包含已知格、碰撞阻挡格、规划阻挡格、网格原点与分辨率、控制位姿、碰撞半径、
米制占据格中心、缓存候选接回点及索引、当前目标及索引、真实路线索引、扫描阶段与原点、参数 JSON。
可用 `numpy.load(path, allow_pickle=False)` 读取；没有有效网格时安全跳过，导出失败不影响原轨迹保存与停车收尾。
`START_MAX_OFFSET_M=2.0` 只用于已确认空旷的起点附近；不要将它理解成任意位置自主返航。

## 预期行为

- 无障碍：按原顺序完成回起点、对齐和路线跟踪。
- 前方新增箱体：停车评估，选择已观察到的侧面路径；先绕到可见区域，再随点云更新接回当前路线前方。
- 侧面可见空间不足：先原地朝起始朝向的 `+0.65 rad → -0.65 rad → 原朝向` 依次观察，
  线速度始终为零，角速度不超过 0.15 rad/s；扫描最多 20 s，完成或超时后停止扫描。
  扫描仍经过相同的完整碰撞审查与点云/里程计新鲜度安全门，碰撞圆已被占据时不得旋转。
- 绕行期间原路线索引冻结；只有实际到达指定接回点才更新进度，不按欧式最近跳到回程支路。
  候选接回点限制在当前路线前方 3 m 的弧长窗口内，并在掉头前截断。
- 两侧都堵或始终没有安全路径：扫描结束后保持零速度并有限重试，当前配置持续堵塞 35 s 后失败退出。
- 点云/原始里程计失效、TF 异常或底盘异常：失败停车，不宣布完成路线。
- 已检测占据保守保留至移出局部窗口或重启任务。搬走障碍不会立即释放旧占据，
  避免高处墙面回波越过低矮箱体时错误地“清除”箱体；首版按静止障碍验收。

高度带是离地 6–80 cm，每个 10 cm 格至少 8 个回波，过滤近场稀疏噪点；首次检出就保留保护。
验收使用宽约 30 cm 以上、高约 20 cm 以上的不透明纸箱，避免用细线、透明玻璃或低于高度带的物体测试。

## 分步实车验收

下列运动试验仅在用户授权后执行。

1. 清空原路线，先以 0.10–0.12 m/s 验证原流程；记录位置/朝向终点判据与是否触发绕行。
2. 将箱子放在路线中段，距初始车头至少 1–1.5 m，两侧留足整车通行空间。先静止确认箱体占据被检测。
3. 再低速跑同一条路线，核对有实际横向绕行、接回日志与最终成功判据；不能把“停在箱前”判为绕行通过。
4. 换另一侧或封住一侧复测；最后验证全堵停车。保留每次日志、`lap_actual_obstacles.yaml`
   及其 `.obstacles.npz` 附属快照，避免覆盖上一轮证据。

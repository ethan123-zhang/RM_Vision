### 操作

1. 架空底盘、四轮离地，清除轮边杂物及线缆，确保可立即断开电机电源。
2. VS Code `Ctrl+Shift+B` 编译，Keil 打开 `MDK-ARM/chassis_task.uvprojx` 按 F8。
   `Verify OK / Application running` 才表示烧写成功。本次代理仅编译，未代烧。
3. 上电保持零电流；KEY 按 N 次（1..4），最后一次之后等待 3 秒，选择 N 号电机。
   超过 4 次清零不执行。本模式暂未添加按键蜂鸣反馈。
4. 仅该轮运行：**+600 rpm 8秒 → 0 rpm 1秒 → −600 rpm 8秒 → 0 rpm 1秒**。
   其余三轮始终零电流。18 秒结束后释放，不永久保持零速。
   2026-10-29 将正反恒速段由各2秒延长至各8秒，便于区分瞬态和稳态；重新烧写后生效。
5. 运行中再按一次 KEY 立即取消。反馈掉线或转速绝对值超过 1500 rpm 同样取消；
   恢复后不会自动续跑，需重新选轮。本模式不使用遥控器，拨杆不能作为急停。
6. 逐一测试四轮并记录。运行中不抓轮子，不以“手拧不动”作为验收依据。

600 rpm 是**电机转子转速**，不是减速箱输出轮转速。

### USB-CAN 观测与验收

新增标准帧 **0x1F2**，25ms 一帧、DLC=8，16位字段均为**有符号大端**：

| 字节 | 含义 |
| :--- | :--- |
| 0 | 运行中的 CAN ID；0=未驱动 |
| 1 | 0=空闲/完成/按键取消，1=运行，2=反馈不可用，3=超速取消 |
| 2..3 | 目标电机转子 rpm |
| 4..5 | 实际电机转子 rpm |
| 6..7 | 输出电流指令 |

+600 rpm 编码为 `02 58`，−600 为 `FD A8`。
`0x1F0` 四轮 rpm（大端）与 `0x1F1` 在线状态继续发送，模式显示 3。
25ms 采样不能排除更快的瞬态振荡。

初步检查选轮、正负反馈、速度跟踪、持续振荡与取消后电流清零；掉线/超速停机仍须上板验证。
正式第一阶段还需记录稳态误差、超调、调节时间，当前不能宣称已调好。
主机测试：`pwsh -File cboard_chassis/tests/run_speed_tests.ps1`，另跑原 `tests/run_tests.ps1` 回归。

## 1. 接线

| C 板 | 接到 | 备注 |
| :--- | :--- | :--- |
| CAN1 `PD0/PD1` | 4 个 C620 的 CAN_H / CAN_L | **H 对 H、L 对 L**，不要接反；线用双绞，别和 24V 捆一起 |
| 120 Ω | 总线两端各一个 | C 板一端 + 最后一个 C620 一端；只装一端时短距离也能通，但长了会随机丢帧 |
| 24 V | C620 电源口 | **不要**从 C 板取电给电机 |
| DBUS（3P） | DR16 接收机 | 上电后接收机灯常亮 = 已对频 |
| SWD | ST-Link / J-Link | 烧写与调试 |

上电顺序（每次都一样）：

1. 只插 USB 给 C 板 → RGB 灯开始流动 = 固件跑起来了。
2. 给 24 V（C620 上的灯亮）→ 此时才允许电机出力。
3. 开遥控器 → 接收机灯常亮。

> 断电顺序反过来：先关 24 V，再拔 USB。

## 2. 四个阶段的调车流程

> 当前默认是**阶段 0（按键验 ID）**。每个阶段都要改 `chassis_bringup.h` 里的
> `CHASSIS_BRINGUP_MODE`，改完重新编译烧写。

### 阶段 0：按键验 ID（默认）

目的：核对"电调里设的编号"和"实际驱动的是哪一路"是否一致。

**车轮必须离地**。这个阶段不看遥控器、不看陀螺仪，只做一件事：

> 按 C 板上的 **KEY** 键 N 次，**停手 3 秒**，第 N 号电调就转 1.5 秒（电流 +900，空载约 1.1 A）。

| 你的操作 | 结果 |
| :--- | :--- |
| 按 1 次，停 3 s | 1 号电调转 |
| 连着按 2 次（间隔 < 3 s），停 3 s | 2 号电调转（计时从**最后一次**按键算） |
| 按 3 次 / 4 次 | 3 号 / 4 号 |
| 按超过 4 次 | 计数清零，**什么都不转**（宁可不转，也不转错） |
| 转动途中再按键 | 不打断这次转动，但会记下来，等下一次 3 s 静默再兑现 |

**转得太快 / 想再慢一点**：空载转速基本正比于驱动电流，改 `chassis_bringup_map.h` 里
`CHASSIS_KEY_SPIN_CURRENT` 一个数就行，时序不用动。

| 该值 | 空载电流 | 表现 |
| :--- | :--- | :--- |
| 2500 | 约 3.0 A | 飞快，看不清（原始值，2026-10-26 已调低） |
| **900** | 约 1.1 A | **当前默认**：慢慢转满 1.5 s，方向一眼能看出来 |
| 700 | 约 0.9 A | 更慢，适合看细节 |
| ≤ 500 | ≤ 0.6 A | 常常起不来：静摩擦顶不过，轮子只“嗡”不转（不是坏了） |

想改“转多久”就改 `CHASSIS_KEY_SPIN_MS`（默认 1500 ms）。
两者都只影响观感，不影响“驱动的是哪一路”。

怎么确认"设备数到的次数"和你按的一致：

| 方式 | 说明 |
| :--- | :--- |
| 蜂鸣器 | 每按一次"嘀"一声（50 ms）。调车模式下 `test_task` 的报警已静音，不会盖掉 |
| `0x1F1` 第 8 字节 | `data[7]` = 当前计数（0~4）。连按 3 次应看到数字爬到 3，转完归 0 |

判断标准：**按 1 次，转的是不是你以为的 1 号**。
转的是别的轮子 → 那个电调的编号设错了，或者两个电调的线插反了；
完全没反应 → 见 §6 故障表最后几行。

### 阶段 1：单电机扫描（把模式改成 1）

把 `CHASSIS_BRINGUP_MODE` 改成 `CHASSIS_BRINGUP_MODE_SWEEP`（1），重烧。

**车轮必须离地**。烧进去以后，周期 20.4 s 无限循环：

| 时间 | 动作 |
| :--- | :--- |
| 0 ~ 0.4 s | ID1 静默 |
| 0.4 ~ 1.6 s | ID1 **正转**（电流 +1000） |
| 1.6 ~ 2.2 s | ID1 停 |
| 2.2 ~ 3.4 s | ID1 **反转**（电流 −1000） |
| 3.4 ~ 4.6 s | ID1 停 |
| 4.6 s 起 | 换 ID2，重复同样的节奏 |
| 18.4 ~ 20.4 s | 四路全零，间歇 |

这一段**不看遥控器、不看陀螺仪**，只要 CAN 通就会转。速度同样由 `CHASSIS_SWEEP_CURRENT`
决定（默认 1000，约 1.2 A；觉得快就改小，低于 ~500 起不来）。

**开机前先确认一件事：四个 C620 的 ID 真的互不相同。**
C620 出厂默认 ID 是 1；如果四个都没设过，分析仪上只会看到一条 `0x201` 在刷，
而扫描时会看到**四个轮子一起转**（它们都在响应 ID1）。这正是"ID 冲突"的典型现象。
设成 1/2/3/4 的方法见《C620 使用说明》（`0x700` 快速设 ID）或官方调参软件；
设完再回到这里。正常应该是 `0x201`~`0x204` 四条帧各 1 kHz。

拿张纸记四行：

| CAN ID | 转的是哪个角（右前/左前/左后/右后） | +1000 时轮子顶部往车头还是车尾走 |
| :--- | :--- | :--- |
| 1 | | |
| 2 | | |
| 3 | | |
| 4 | | |

然后填 `chassis_bringup_map.h` 的两张表：

```c
/* 轮位：0=右前 1=左前 2=左后 3=右后（官方解算顺序） */
#define CHASSIS_WHEEL_CAN_ID_0  1   /* 右前是哪个 ID */
#define CHASSIS_WHEEL_CAN_ID_1  2   /* 左前 */
#define CHASSIS_WHEEL_CAN_ID_2  3   /* 左后 */
#define CHASSIS_WHEEL_CAN_ID_3  4   /* 右后 */

/* +1000 时轮子顶部往车头走填 +1，往车尾走填 -1 */
#define CHASSIS_WHEEL_DIR_0 (+1)
#define CHASSIS_WHEEL_DIR_1 (+1)
#define CHASSIS_WHEEL_DIR_2 (+1)
#define CHASSIS_WHEEL_DIR_3 (+1)
```

四个 ID 必须互不相同。写重复或越界时，**切到正常模式后**固件会在启动时响三声，
并且四路电流恒为 0（宁可不转，也不能乱转）。扫描阶段不查这张表，所以扫描照样能转——
这也是为什么阶段 1 可以放心先扫、后填表。

### 阶段 2：遥控通道确认

把 `CHASSIS_BRINGUP_MODE` 改成 `CHASSIS_BRINGUP_MODE_NORMAL`（0），重烧。
**先不要下地**，或者把 S1 拨到最下面（这个档位是 NO_MOVE，车不动，但遥控数据照常进来）。

用 USB-CAN 分析仪看 `0x1F1`：

| 字节 | 含义 | 期望 |
| :--- | :--- | :--- |
| `[0]` | 在线掩码，bit0..3 = 轮位 0..3 | 四个都在线 = `0x0F` |
| `[1]` | `S1 | (S2 << 2)` | 拨 S1/S2 时数值变；1=上 2=下 3=中 |
| `[2]` | 左摇杆上下 ÷8 | 中位 ≈ 0（死区 ±10），推到顶 ≈ ±82 |
| `[3]` | 左摇杆左右 ÷8 | 同上 |
| `[4]` | 右摇杆左右 ÷8 | 同上，这是自转通道 |
| `[5]` | 调车模式 | 0 = 正常，1 = 扫描，`0xFF` = **标定表非法** |
| `[6]` | 遥控在线 | 1 = 在线 |
| `[7]` | 底盘状态机；**按键模式下 = 当前按键计数** | 0 跟随云台 / 1 跟随底盘 yaw / 2 不跟随 / 3 RAW |

`[2]~[4]` 恢复真实通道值：读到的数 **×8**。

S1（左开关）在官方代码里的含义：

| S1 | 行为 | 用在哪 |
| :--- | :--- | :--- |
| 上 | 跟随底盘 yaw 角（角度闭环，**依赖陀螺仪**） | 正常打比赛 |
| 中 | 不跟随：左摇杆平移，右摇杆左右自转 | **调车就用这一档** |
| 下 | NO_MOVE，原地不动 | 查通道、急停 |

### 阶段 3：整车

还是阶段 2 的固件（模式 0），车轮落地，S1 拨中，慢慢推：

1. **推前进（左摇杆上）**：四个轮子都应向前滚，车走直线。
   哪个轮子倒转 → 改它的 `CHASSIS_WHEEL_DIR_i` 取反。
2. **推左移（左摇杆左）**：车应整体向左平移，不转。
   如果变成原地自转 → 说明某个 ID 装错了角，交换对应的两个 `CHASSIS_WHEEL_CAN_ID_i`。
3. **推右摇杆左右**：车应原地转，推右往右转。
   方向反了 → 同样属于"角装错了"，交换一对 ID。

判断口诀：

| 现象 | 说明 | 改哪里 |
| :--- | :--- | :--- |
| 某个轮子**所有方向**都反 | 只是极性反 | `CHASSIS_WHEEL_DIR_i` 取反 |
| 某个轮子前进时对、横移时反 | 这个 ID 被放到了错误的角上 | 交换两个 `CHASSIS_WHEEL_CAN_ID_i` |
| 车能走但总是往一侧偏 | 机械/轮径/PID，不是标定 | 见 §5 |

标定完把这次的结果记在下面，下次换车/换线直接对照：

## 3. 调试 CAN 帧

只在 `CHASSIS_DEBUG_CAN = 1` 时发；不需要时置 0，总线上就只剩电机的帧。

| ID | 周期 | 内容 |
| :--- | :--- | :--- |
| `0x1F0` | 25 ms | 4 个轮位的**实际转速**，int16 大端：`[0:1]` 轮位0，`[2:3]` 轮位1，`[4:5]` 轮位2，`[6:7]` 轮位3，单位 rpm（转子侧） |
| `0x1F1` | 100 ms | 状态，见上表 |

`CHASSIS_WHEEL_CAN_ID_i` 换了以后，`0x1F0` 里的顺序也跟着换（它按轮位排）。

电机本身的帧（C620 回传，1 kHz）：

| ID | 内容 |
| :--- | :--- |
| `0x201` ~ `0x204` | 对应 ID 1~4：`[0:1]` 编码器，`[2:3]` 转速 rpm，`[4:5]` 实际电流，`[6]` 温度 ℃ |

控制帧 `0x200`（2 ms 一帧）：`[0:1]` ID1、`[2:3]` ID2、`[4:5]` ID3、`[6:7]` ID4 的电流，范围 −16384 ~ 16384（对应 ±20 A）。
扫描模式下，看 `0x200` 哪个位置非零，就知道现在在测哪个 ID。

## 4. PID 怎么调

默认值在 `chassis_task.h`（官方原值，没动）：

```c
#define M3505_MOTOR_SPEED_PID_KP 15000.0f
#define M3505_MOTOR_SPEED_PID_KI 10.0f
#define M3505_MOTOR_SPEED_PID_KD 0.0f
```

速度环输入输出都是"轮子线速度 m/s"，输出是 C620 电流值。

| 现象 | 调整 |
| :--- | :--- |
| 起步一顿一顿、来回晃（低频振荡） | 降 `KP`（15000 → 12000 → 10000） |
| 推满摇杆速度上不去、稳态差一截 | 加 `KI`（10 → 20 → 30） |
| 高频啸叫、电机发烫、声音尖 | 降 `KP`，或把 2 ms 周期改 3~5 ms 试 |
| 刹车/换向时冲过头 | 加一点 `KD`（先试 50~200） |

看 `0x1F0` 的 rpm 曲线：给一个阶跃（摇杆瞬间推到底），正常应在 0.1~0.2 s 内稳定，允许一次小过冲；等幅振荡就是 `KP` 太大。

## 5. 全向轮 vs 麦轮（这台车是 4 轮全向）

4 轮全向 **45° X 型**装法，运动学和麦轮**符号完全一样**，只差一个 1/√2 系数：

```
麦轮/全向通用：  FL = (vx − vy)/s − k·wz
                FR = (vx + vy)/s + k·wz
                RL = (vx + vy)/s − k·wz
                RR = (vx − vy)/s + k·wz      （s = 1 麦轮，s = √2 全向）
```

所以官方这套解算**不用改**，只是：

- 给定 `vx = 1 m/s` 时，车实际跑约 **1.41 m/s**（那个 1/√2 被吸收进速度常数里了）。
  现在只是调车，不影响；以后要拿 `vx` 当真实速度做导航，再把
  `M3508_MOTOR_RPM_TO_VECTOR` 和 `MAX_WHEEL_SPEED` 一起乘 0.7071。
- 前提是轮子确实按 **X 型 45°** 装的。验证方法：手推车向正侧面，
  四个轮子都跟着滚、车能平移 → X 型；如果只能前后、侧面推着走打滑 → 那是平行装法，
  解算要换（到时候告诉我）。

## 6. 故障对照表

按"看到什么"从上往下查：

| 现象 | 先查 | 说明 |
| :--- | :--- | :--- |
| 上电灯不流动 | USB 供电 / 固件是否真烧进去 | 灯流动 = 调度器跑起来了 |
| 灯流动，但扫描模式下四个轮子都不动 | `0x200` 帧有没有发出来 | 有 `0x200` 没 `0x20x` → CAN 物理层问题 |
| 扫描时**四个轮子一起转** | 四个 C620 都是出厂 ID 1 | 先按说明书把 ID 设成 1/2/3/4 |
| **按 KEY 没反应、蜂鸣器也不响** | 确认烧的是阶段 0 的固件（`0x1F1[5]` 应为 2） | 模式不对时按键不会驱动任何电机 |
| **按 KEY 有"嘀"声，但 3 s 后没轮子转** | `0x1F1[7]` 数到几、`0x1F1[0]` 是否 `0x0F` | 数是 0 → 按键被当成超界清掉了；数对、四个都在线但**四个都不转** → `CHASSIS_KEY_SPIN_CURRENT` 太小（静摩擦顶不过），调到 1200；数对但**只有某一路**不转 → 那个电调没通 |
| **转的是别的轮子** | 对比按下次数和实际转的轮子 | 电调编号设错，或两根 CAN 线插反 |
| 四个电机都无回传 | CAN_H/L 反接、120 Ω 缺失、C620 没上 24 V、波特率不是 1 Mbps | 先量 C620 电源灯 |
| 只有某一个无回传 | 那个 C620 的 ID 被改过 / 线断 / 端子松 | 用分析仪看 `0x20x` 缺哪个 |
| 有回传，但轮子不转 | C620 报故障（红灯闪码见《C620 使用说明》故障排除章节）、电机三相线 | 回传里的温度/电流也能看出异常 |
| 扫描都正常，整车推摇杆不动 | `0x1F1[6]` 是否 = 1；S1 是否在最下面；`0x1F1[0]` 是否 = 0x0F；`0x1F1[5]` 是否 = 0xFF | 这四项能覆盖 90% 的"不动" |
| 一动就往一边跑 | 机械：轮子没装正/地面不平；轮径不一致 | 不是标定问题 |
| 车能走但抖 | PID | 见 §4 |
| 蜂鸣器一直响 | 正常模式下 `test_task` 在对掉线设备报警 | 这个工程没有云台，yaw/pitch/trigger 永远掉线，所以会一直响；调车模式已自动静音 |

`0x1F1[5] = 0xFF` 且启动时响三声 = **标定表写错**（ID 越界或重复），
这时四路电流恒 0，改好表重烧即可。

### 7.3 三条路都试过，只有 F8 能用

| 路径 | 结果 | 原因 |
| :--- | :--- | :--- |
| **Keil 界面 F8** | ✅ 可用 | 唯一可靠路径 |
| Keil `UV4 -f`（命令行） | ❌ 必崩 | 破解版批处理模式，`exit=0xC0000409`，无日志 |
| **STM32CubeProgrammer** | ❌ **禁用** | 同一 ST-Link，Keil 能连、它连不上（`No Device ID`）；DFU 模式也放弃 |

`UV4 -b`（命令行编译）**可以用**，但有个坑：在 Keil 里按过一次 F8 之后，
`MDK-ARM/DebugConfig/` 会让 `UV4 -b` 也崩（同样 `0xC0000409`）。
`tools/flash.ps1` 每次编译前会自动删掉这个目录，手动跑命令时要注意。

**踩过的顺序坑**（都是真实发生过的，按发生顺序记）：

1. **缺 `Keil.STM32F4xx_DFP`** → `UV4 -f` 静默不动（退出码 0、日志 0 字节）。
   装包后才有 F4 的 Flash 算法。
2. **Debug 选项卡选成 `ULINK2/ME`** → F8 报 `No ULINK2/ME Device found`。
2. 改成 **`ST-Link Debugger`** 才通。
3. **CubeProgrammer 全程在骗人**：它连 ST-Link 都连不上，但会报出 SN/FW/电压，
   看起来像"芯片没应答"，把排查方向带偏了整整一轮。
   **结论：这台机器上不要再用它烧录，也不要用它的 `-l`/`-c` 输出判断硬件好坏。**

### 7.4 SWD 接线备忘（以后用到再看）

- ST-Link 的 2×5 排针是**奇偶两排交错**的：SWCLK=②、SWDIO=④、GND=⑤/⑥、3.3V=⑦/⑧；
- 板子那边丝印顺序通常不同，**不要用 4 针连体插头横插**，一根一根按名字接；
- ST-Link 的 3.3V 可以不接（板子自己供电），少一根线少一个坑；
- Keil `Debug → Settings` 的 **SW Device** 里能看到 `IDCODE 0x...` 才算真连上。

纯逻辑自测（改标定表后建议跑一遍）：

```powershell
pwsh -File E:\RM\cboard_chassis\tests\run_tests.ps1
```

四套标定表各编译一次：恒等、打乱、重复 ID、ID 越界，共 263 项断言
（含按键状态机的 3 s 边界、连按重置、转动中按键、超界清零）。

| 文件 | 改动 |

**行为差异**（都是有意的）：

1. 启动不再死等：等 4 个电机 + 遥控器最多 3 s，超时继续跑（没遥控只发 0 电流）。

## 9. 已知限制 / 下一步

- `vx / vy / wz` 不是真实物理单位（全向轮 1.41 倍），导航前要统一。
- 没有上位机（X5）控速接口，现在只能遥控。
- 没有在线改 PID，改参数要重烧。
- 按键验 ID 只驱动 1~4 号（`0x200` 一帧）；如果电调编成了 5~8 号，要再加 `0x1FF` 那条。
- 单电机扫描只看转向和 ID，不测编码器零位（3508 不需要）。

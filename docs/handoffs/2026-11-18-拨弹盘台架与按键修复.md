# 2026-11-18 拨弹盘台架：模式 5 重做 + 按键极性修复

## 结论

拨弹盘台架模式（`CHASSIS_BRINGUP_MODE = 5`）已从"按档位脚本跑 7 秒"改成**比赛用法"按住转 / 松开刹车停"**，
上板实测通过（用户 2026-11-18 确认"ok 了"）。测试目标同步从"验收口径"降级为**比赛可用性四项**，
T3「空盘最高转速」取消。

## 发生了什么

1. **测试目标被推翻（用户决定）**：比赛用法是固定送弹速率、按住才送；3V3 冷却优先每发 +10 热量、
   冷却 24/s，持续射速上限 2.4 发/秒（≈盘轴 8 rpm）——"最高转速"与比赛表现无关。
   规格文档 T3 及手机 240 fps 复核取消，只在 handoff 里留历史标注。
2. **台架固件重写（模式 5）**：原先"KEY 按 N 次选 50/100/150/200 rpm、脚本 7 秒"。
   新行为：短按 KEY 切档、按住 ≥0.3 s 开转、松开主动刹车、按住超过 20 s 自动断（防按键卡住）。
   档位改为竞赛可用段：盘轴 10/20/30/50 rpm ≈ 3/6/9/15 发/秒。
3. **按键极性 bug（关键）**：第一版把 `HAL_GPIO_ReadPin` 的 `GPIO_PIN_RESET`(0) 直接当"按下"返回，
   导致逻辑整体反转——**上电自己转、按键反而停**。用户上板发现"逻辑跟说的不是一回事"。
4. **修法**：极性只在 `trigger_bench_key_raw_pressed()` 一处翻译成"1 = 按下"；按键状态机
   （去抖 20 ms / 短按 <300 ms / 按住 300 ms / hold 事件只报一次）抽到纯逻辑模块
   `trigger_bench_logic.c`，主机 gcc 测试钉死时序与极性；上板重烧后确认正常。

1. **空盘基线**：`chassis_task.hex` 已烧；上电不碰 → 应完全不动；短按 1 次 → 响 1 声（1 档）。
2. **连续送弹**：装收集罩，1 档装 10 发，按住送完，填 `runs.csv` 的 `continuous` 行（计划/实际/卡滞/干预）。

5. 结果回填后，把"可用档位 / 各档送弹速率 / 过冲发数 / 断电失力"写进实验 README 第 6 节。

## 未完成 / 风险

- **S44 / S45 整机项仍未验证**：拨弹盘单体测不出"稳定发 10 发"和初速度，需要摩擦轮发射机构 + 17 mm 测速模块。
- **S114 断电验收**未做：需要裁判系统电源管理模块（Ammo-Booster 接口）+ 同步电压记录。
- 固件默认模式是 5；**回底盘调车/跑车前必须把 `chassis_bringup.h` 默认值改回 3 或 0 重烧**。
- 电流环增益（Kp 0.5 / Ki 0.002）未按负载整定；带弹卡滞时依靠失速判据停机，不保证不卡。
- 惯性滑行量（松手后多送几发）取决于当前刹车 P 值，实测后可能要调。

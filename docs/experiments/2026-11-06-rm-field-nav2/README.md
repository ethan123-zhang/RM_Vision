# RMUL2027 3V3 场地接进 Nav2 + 围栏碰撞验收（2026-11-06）

短记：这一轮把 2026-11-01 留的两条欠账补完 —— 围挡到底挡不挡得住、场地能不能给 Nav2 用。
两块都用可复跑的判据收口，结论写进 `tb3_gazebo_nav2/rm_field/README.md` §11。

## 起点

2026-11-01 场地已 1:1 进 Gazebo（比例/碰撞/台面高度/观感四项量化验收），但留了两条：

1. 围挡只有 `visual + collision` 定义，**从没测过能不能挡住车**；
2. 场地是"能看能开"的状态，**没接进 Nav2**（没有地图，规划器无处可规划）。

## 轮次 1：围栏碰撞验收（`verify_fence.py`）

判据分三类，全部是读数：

| 测试 | 做法 | 结果 |
|---|---|---|
| 围挡顶是实体 | 4 个探针从 z=0.70 落在四条围挡中心线 | 4/4 停在 **z=0.300**，最大偏差 0 |
| 围挡外侧是空的 | 2 个探针放在 (6.40,0)/(0,4.40) | 2/2 落到 **−0.503** |
| 撞墙不越界 | `/cmd_vel` 0.7 m/s 连续 16 s 顶东/北围挡 | 停在 **6.1819 / 4.1820**（理论 6.1815/4.1815，误差 0.4/0.5 mm），`crossed_inner=false`，z 恒定 0.010，末 3 s 漂移 0 |

停位理论值不是拍脑袋：TB3 碰撞盒 0.265 m、盒心后移 0.064 m → 车头前表面在中心前 0.0685 m，
围挡内侧面 6.250 − 0.0685 = **6.1815**。实测差 0.4 mm，说明"车头贴住围挡"是可量的。

**踩坑**：第一版抖动判据取"最后 3 s 位移"，得到 0.63 m（≡12.6 m/s，物理不可能）—— 是 Gazebo
pose 采样的一次瞬跳。改为先剔除步长 >0.15 m 的跳变再算漂移，重跑 `jumps=0`、漂移 0.0，两次一致。

## 轮次 2：顶视渲染 → Nav2 地图

**决定：地图按 CAD 几何生成，渲染图只做独立校核**（与最初设想的"渲染图二值化"不同）。
原因：渲染有阴影（东/南台面边一条 0.15 m 暗带）、透视（红顶沿在 z=+0.33，投影外扩 ~0.15 m）、
抗锯齿，二值化边界会带 1~3 px 系统偏差；而内侧面位置是定义值，不该被渲染噪声污染。

- 地图：512×352 @ 0.025 m/px（12.5/0.025=500、8.5/0.025=340 正好整数像素），origin (−6.40,−4.40)，
  自由区 |x|<6.25 且 |y|<4.25，其余全 0 → 自由区面积可精确断言 **106.25 m²**。
- 校核（20 m 正俯视 1600×1100，f=2000 px）：受光台面 **12.500×8.500 m**、
  围挡中心线 **12.5492×8.5465**（图纸 12.550/8.550）、红顶沿环心偏差 **4.9 mm**、
  地图自由区 bbox **12.500×8.500 m** —— 8/8 判据通过。

## 轮次 3：Nav2 闭环（`nav2_field.sh` + `verify_nav2_field.py`）

`nav2_bringup/tb3_simulation_launch.py` + 自写 xacro 世界（围挡场地 + Sensors/IMU 系统，
接受 `headless` 参数）+ 自建地图 + nav2 默认参数 + `nav2_minimal_tb3_sim` 的机器人与桥接。
起点 (0,0)，AMCL 初始位姿发三次（不发就 planner_server 起不来，老坑）。

| 判据 | 实测 |
|---|---|
| 链接 | /scan 4.3–5.0 Hz、/odom 27–29 Hz、RTF 0.94 |
| 目标 (4,2) | SUCCEEDED、error_code 0、恢复 0、11.6 s、4.335 m、终点距目标 0.179 m |
| 目标 (0,0) | SUCCEEDED、error_code 0、恢复 0、27.0 s、4.824 m、终点距目标 0.037 m |
| 不出界 | max|x| 3.875、max|y| 1.877（限 6.10/4.10） |
| 不掉落 | z 恒 0.010 |
| 速度 | `cmd_vel` 峰值 0.496 ≤ 参数 vx_max 0.5 |

**两个坑都是判据本身错，不是系统错**：

1. 用 `/amcl_pose` 算终点/时长 → "11.4 s 走完 4.47 m"（0.39 m/s）。AMCL 只在移动 >0.25 m 或转
   >0.2 rad 时发布，端点会滞后半米。改用 TF `map→base_footprint` 连续采样 + 区分 wall/sim 时间。
2. 凭印象写"TB3 上限 0.26 m/s"→ 实测 0.38 判失败。查 `nav2_params.yaml` 是 `vx_max: 0.5`
   （TB3 底盘不限速，快慢完全由参数决定）。改成从参数文件读上限，再用 `/cmd_vel` 实测峰值对比。

**为什么 Nav2 必须用带围挡的世界**：0.503 m 台沿在 lidar 扫描平面（z≈0.11）之下，1:1 世界对
AMCL 是空场、只有里程计；0.30 m 围挡横在扫描平面上，±6.25/±4.25 才有真实墙面可定位。

## 复跑

```bash
cd tb3_gazebo_nav2/rm_field
bash run_fence_test.sh                            # 围栏验收（~70 s）
bash capture_nav_map.sh                           # 顶图 → 地图 → 校核（~40 s）
bash nav2_field.sh && python3 verify_nav2_field.py && bash stop_nav2_field.sh   # Nav2（~2 min）
bash nav2_field.sh --gui                          # 想看画面：Gazebo GUI + RViz
```

## 遗留

1. 场地目前是空矩形：绕障、动态避障、多目标巡逻未测。
2. 参数用 nav2 默认值，没按 12.6×8.6 场地调（inflation 0.55 m 会吃掉一部分通道宽度）。
3. 围挡高度 0.30 m 与赛规一致性未核对。

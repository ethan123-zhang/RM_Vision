# 第二阶段任务计划：四轮联动、解算核对与低速基础运动

> 执行约定：下次会话逐项使用executing-plans执行并在各任务后核对证据。本次只保存计划，不实现、不烧写、不启动第二阶段；未创建新会话或自动任务。

**目标：** 在可观察、限速限流且可停止的条件下，完成六方向基础运动，形成轮位/方向/单位与停止行为的验证记录。

**架构：** 保留官方框架及现有模式0～3，建议新增模式4作为受限四轮测试入口。四轮各自使用已验证的rpm PI，经轮位/方向映射后统一发CAN；先架空核对，完成单轮验收残项和遥控停止验证后再低速落地。

**技术：** STM32 C板、C620/M3508、CAN、C99主机测试、Keil AC5、Python离线CAN分析。无需引入导航或新的通信链路。

**设计依据：** [第二阶段设计](../specs/2026-10-29-cboard-stage2-design.md)。

## 全局约束与边界

- 第一阶段标记为“基础功能完成，定量验收未完成”。任务0未通过前，后续只允许主机设计与测试，不启动四轮联动。
- 不改变当前默认模式3、不提高Ki=0.004或限流作为会话收尾动作。模式4仅是拟议实现，尚不存在。
- 保留Kp=2、Ki=0.004/2ms、积分限幅400、单轮输出指令±1500、每轮目标不超过±600转子rpm，除非独立实验提供修改依据。
- rpm不等于轮速或车体m/s；官方模式0的增益与16000电流上限不能直接当作本阶段已验证设置。
- 不同时更改增益、滤波、解算符号及几何；每项变更分别留基线、测试和提交。
- 先确认真实轮型与几何，不依据“轮外侧看正转均顺时针”自动填全+1。
- 烧写仅使用Keil界面F8；不使用UV4命令行烧写或STM32CubeProgrammer。
- 原始记录各轮独立保存，异常与正常片段并存，不覆盖本次五轮记录及本地归档。
- IMU航向保持/坐标解耦、功率保护、融合里程计和导航不属于本阶段；四轮同时出力前仍需核对供电裕量。

## 任务0：先收口第一阶段，确定第二阶段进入资格

**文件：** 阅读`docs/experiments/2026-10-29-single-wheel-session/README.md`、Ki对照及3号补测；建立`docs/experiments/stage1-acceptance/README.md`和对应采集目录；更新PROGRESS。

**输入：** 五轮原始记录、当前Ki=0.004固件、2号换线事实。

**输出：** 已确认的验收阈值、四轮重复测试结果、是否允许进入第二阶段的明确结论。

- [ ] 在下一会话开始确认下表建议阈值；可根据用途调整，但必须先记录再测试，不能事后用结果倒推标准。

  | 指标 | 建议起点，尚待确认 |
  | :--- | :--- |
  | 最后2秒平均误差 | 每方向≤2%目标值 |
  | 最后2秒原始速度标准差 | ≤5%目标值，同时报告极值与95%误差范围 |
  | 瞬时超调 | ≤20%，按原始反馈说明采样限制 |
  | 慢响应调节时间 | 0.25秒移动平均进入±5%并保持至段末至少1秒，建议≤3秒；另报原始波动，不以平滑曲线替代原始验收 |
  | 零速及释放 | 零速末0.5秒绝对值≤5rpm；退出后四路指令为零 |
  | 重复性 | 固定可靠接线下，每轮正反完整测试至少两次 |

- [ ] 固定检查2号CAN接线并记录更换后的接线/供电条件，不在运动中插拔；先零指令确认四轮反馈及状态。
- [ ] 连续接收至少60秒零指令基线，再完整重复四轮；异常时单独归档并退出整定判断，恢复后重新采集完整轮次。
- [ ] 对未满足指标的轮子，按原始反馈、电流与角度分析决定单变量实验；若采用滤波，保留未滤波原始指标并比较延迟。不要预先承诺某种滤波能解决物理纹波。
- [ ] KEY、反馈不可用和超速保护分开列证据；超速主机用模拟反馈测试，不以故意高速旋转方式制造超速。上板未测的项明确保留。
- [ ] 写入“通过/未通过/受限通过及适用范围”。目前不能预填通过；若未通过，继续第一阶段，第二阶段运动任务不执行。

## 任务1：确认安装几何与方向表

**文件：** 阅读`chassis_bringup_map.h/.c`和`chassis_task.c`；新增`docs/experiments/stage2-wheel-geometry/README.md`；确认后才修改`CHASSIS_WHEEL_DIR_0..3`。

**输入：** 轮位ID表、安装照片/观察、每轮正转方向；任务0进入许可。

**输出：** 实际轮型、安装角、轮位坐标、轮径、减速比来源及方向表的记录。未测量项不写成已知物理常数。

- [ ] 以1/2之间为车头标注FR/FL/RL/RR，确认全向轮安装形式及每轮驱动切向，记录轮距/轴距与旋转中心。
- [ ] 明确机体系x前、y左、z逆时针；列出三类纯分量的轮位符号和对应裸CAN方向，人工核对。
- [ ] 为方向表的反馈和输出路径建立一张同源转换表：逻辑反馈=`方向×裸反馈`，裸电流=`方向×逻辑电流`。用实际数据核对不会出现正反馈。
- [ ] 在主机测试覆盖混排ID、负方向、非法/重复ID；运行原四套映射测试并记录263项回归结果。修改表前后保留快照。
- [ ] 若几何不符合对称45°模型，先重写几何设计及黄金向量，不把下方候选矩阵直接上板。

## 任务2：实现可主机测试的受限四轮目标生成

**拟新增文件：** `cboard_chassis/application/chassis_vector_test.h/.c`、`cboard_chassis/tests/test_vector.c`、`cboard_chassis/tests/run_vector_tests.ps1`。

**拟议接口：**

```c
/* 输入是机体分量的转子rpm等效量，不是m/s、rad/s。 */
void chassis_vector_mix(int16_t x_rpm, int16_t y_rpm, int16_t turn_rpm,
                        int16_t wheel_rpm[4]);
void chassis_vector_scale_limit(int16_t wheel_rpm[4], int16_t limit_rpm);
```

上板适配只消费四轮目标数组；混合函数不含HAL、FreeRTOS或真实CAN调用。结合任务1的实际几何确认后再冻结接口和矩阵。

- [ ] 先写并执行对称模型的黄金向量测试，观察新增接口尚未实现导致失败；黄金值直接列出，不用被测混合函数反算期望。

  ```c
  /* 仅在任务1确认对称模型后采用，顺序FR/FL/RL/RR。 */
  /* x=300,y=0,turn=0 => {-300, 300, 300,-300} */
  /* x=0,y=300,turn=0 => {-300,-300, 300, 300} */
  /* x=0,y=0,turn=300 => {-300,-300,-300,-300} */
  /* 三分量全零 => {0,0,0,0}；各分量取负则对应输出全反号。 */
  /* x=600,y=600,turn=0，限幅600后 => {-600,0,600,0}。 */
  ```

- [ ] 在确认模型下最小实现混合和等比例限幅；中间计算用足够宽的整数，避免三分量相加溢出。限幅不独立截断各轮，保留组合方向比例。
- [ ] 增加目标斜坡与有限序列测试：建议最大斜率300rpm/s，每2ms目标增量不超过0.6rpm，内部用浮点或余数累积，不能用每周期整数0rpm导致斜坡不动。
- [ ] KEY选择组1前后、组2左右、组3正反旋转；超界选择不运行。每组先斜坡到300rpm、保持、回零及反向，明确各段和总时长；运行中KEY取消立即清零，不将取消键排为下一次动作。
- [ ] 为计时边界、32位时间回绕、取消优先、非法选择、完成后释放建立行为测试。完成后写明实际时序，再进入上板适配。
- [ ] 运行新测试、原速度测试与映射回归，按明确路径提交本项变更。

## 任务3：接入模式4、四路独立PI及统一停止

**拟修改文件：** `chassis_bringup.h/.c`、`chassis_task.c`、`MDK-ARM/chassis_task.uvprojx`，以及任务2模块/测试和README。默认模式仍保持3，测试模式通过显式配置选择4。

**输入：** 四轮rpm目标、实际映射/方向、四轮原始反馈、KEY/反馈健康状态。

**输出：** 每2ms最多统一发送一帧四轮指令；停止时四轮零指令并复位四个积分器。

- [ ] 先测试任一轮失联、超速、映射错误及取消导致四路指令全零；测试恢复反馈后不会自动续跑。四个PI状态必须独立，不能复用同一个积分状态。
- [ ] 增加模式4分支和运行函数；逻辑反馈、PI输出及CAN映射使用任务1确认的统一方向约定，避免对方向重复取反。
- [ ] 加入四轮目标等比例限幅、逐轮±1500电流限幅、有限动作时长和退出释放。不得沿用官方模式0的16000上限。
- [ ] 检查0x1F3是否空闲；若可用，添加设计中的轮询诊断帧，保留模式3的0x1F2语义。原始反馈和0x200仍为高频证据源。
- [ ] 运行主机测试并Keil编译，要求0错误0警告；只在用户准备好实际上板测试时提供模式4固件和F8烧写步骤。
- [ ] 保存模式3回退构建及本项参数指纹。四轮供电条件不清楚时只完成离线适配，不启动同时出力。

## 任务4：四轮架空联动验收

**拟新增记录：** `docs/experiments/stage2-airborne/README.md`、独立原始采集目录、解码CSV、曲线和摘要；更新方向表仅针对已确认的错误。

- [ ] 接线固定、底盘可靠架空，确认四轮反馈在线、供电余量和停止入口；采集先收帧再触发。
- [ ] 先仅执行前后组，核对每轮物理旋转、逻辑反馈符号和裸CAN指令；异常即停止定位，正确后再左右组、旋转组。
- [ ] 每组至少两次，记录目标/反馈、电流、在线掩码、取消/释放及供电变化；任何一轮异常应使四轮停止。
- [ ] 核对组合动作是否按共同倍率限幅、目标是否满足斜坡约束；不以架空轮子“看起来方向差不多”替代符号记录。

- [ ] 先前进、后退，再左右横移，最后双向旋转；各方向至少两次。每次留出静止段，记录实际距离、用时、侧偏、角度及停止过程。

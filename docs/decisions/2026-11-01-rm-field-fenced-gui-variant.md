# 决策：围挡做成“可选变体世界”，1:1 图纸世界保持验收基线（2026-11-01）

## 背景

RMUL2027 3V3 场地 CAD 里**没有**围挡。用户希望在 Gazebo 里“看得出这是一块 0.503 m 高的台子”，
并直接指出“没看到围栏”。围挡同时能解决“机器人一开出边就掉到 −0.503 m 地面”的可用性问题。

## 决定

1. **1:1 图纸世界不动**：`worlds/rmul2027_3v3_field.sdf` 仍是不带围挡的场地本体，
   作为比例/碰撞/台面高度的验收基线（`verify_field.py`、`verify_height.py` 全部指向它）。
2. **围挡单独成模型 + 单独成世界**：`models/rmul2027_3v3_fence/`、`worlds/rmul2027_3v3_field_fenced.sdf`。
3. **GUI 默认加载带围挡世界**（`gui_final.sh` 的 `WORLD` 默认值），要 1:1 世界用
   `WORLD=$PWD/worlds/rmul2027_3v3_field.sdf bash gui_final.sh`。
4. 围挡参数：0.30 m 高、5 cm 厚、贴四边内沿（x=±6.275 / y=±4.275）、4 个 box 碰撞体、浅灰 + 红顶沿。

## 理由

- 图纸里没有的几何不进基线，避免“验收世界”和“交互世界”混为一谈后比例结论失真。
- 围挡是**竖直参照物**：只靠配色，12° 俯角下整场仍容易被读成薄片；立一圈墙后高度关系一目了然。
- 变体开关写在命令行里（`WORLD=`），不需要改文件，也不会忘记“当前跑的是哪一版”。

## 代价 / 风险

- 两套世界要同步维护配色与光照（现已在 §10 里写成同一组数值）。
- 围挡碰撞尚未实测；0.30 m 高度是工程估计，赛规有数值时应改。
- 带围挡世界的“边缘掉落”行为与 1:1 世界不同，机器人测试要在正确的前提下解读。

# 遥控器 DBUS 收不到：有字节但没有 18 字节 0xA9 帧

- 日期：2026-10-22
- 环境：RDK X5 Ubuntu 22.04 / C8T6 STM32F103C8T6 / DT7 遥控器 + 接收机（型号待确认）/
  SN65HVD230 + XHSMCUW50 / CH340 USB-TTL
- 关联：`car_slam_lap/WIRING.md`、`car_slam_lap/README.md` §11、
  `firmware/C8T6_DT7_car/Hardware/UART/DBUS.c`

## 现象

X5 的 `/car/status` 一直只有：

```json
"status": 19,
"flags": ["can_ok", "link_ok", "can_ack"],
"src": "serial"
```

没有 `rc_ok`。烧了带调试位的固件后变成：

```json
"status": 51,
"flags": ["can_ok", "link_ok", "can_ack", "uart2_rx"]
```

即 **USART2 收到过字节，但从未凑成完整 18 字节 DBUS 帧**（`dbus_frame` 不置位）。

## 复现步骤

1. 接收机 5V 供电、LED 常亮（已对频）、遥控器开机；
2. 信号线接 C8T6 **PA3**（USART2_RX），共地；
3. X5 起 `bridge_node --port /dev/ttyS1`；
4. `ros2 topic echo /car/status`，`rc_ok` 始终不出现；
5. 调试固件 `status=51`，`uart2_rx=1`、`dbus_frame=0`。

## 排查过程

已确认：

| 项 | 结果 |
| :--- | :--- |
| 接收机 LED | 常亮（已对频） |
| 信号线 | 接 PA3（USART2_RX） |
| 接收机端口 | 标称 DBUS |
| 共地 | 已补，接收机与 C8T6 共地 |
| PA3 空闲电压 | 3.3V 左右（注意：PA3 有上拉，可能掩盖接收机真实输出） |
| USART2 字节 | 调试位 `uart2_rx=1`，确实有字节 |
| 完整 DBUS 帧 | `dbus_frame=0`，没有 |

USB-TTL 抓包（CH340，COM15，**100000 8E1**，3 秒 3857 字节）：

```text
00 04 20 00 01 78 00 00 00 00 00 00 00 00 00 00 00 04
00 04 20 00 01 78 00 00 00 00 00 00 00 00 00 00 00 04
...
```

- **18 字节一个周期**（正好是 DBUS 帧长）；
- 但全程 **没有 `A9`**，也没有 SBUS 的 `0F`；
- 换 115200 后字节值变成 `00 0C 40 00 01 F0...`（随波特率缩放），说明读到的可能是被错误采样的脉冲/反相信号。

## 根因

**尚未确认。** 目前有三个候选：

1. **CH340 在 100000 波特率下采样不准**（克隆芯片/时钟误差）；
2. **信号反相**：接收机实际输出 SBUS（100000 8E2、反相、25 字节、0x0F），
   C8T6 的 USART2 按 DBUS 8E1 非反相解，永远对不上；
3. **接收机不是标准 DR16 DBUS**（例如 Phantom 3 接收机，输出 SBUS/PPM）。

## 解决

**未解决。** 下一步按顺序：

1. **换 USB-TTL**：用 CH343（设备管理器里曾出现 COM19）或 CP2102 重抓 100000 8E1；
   - 若 CH343 能读出 `A9 ...`，说明是 CH340 的锅；
   - 若还是 `00 04 20...`，说明接收机输出不是标准 DBUS。
2. **量接收机自己的信号脚**（不是 PA3，PA3 有上拉会骗人）对接收机 GND：
   - 3.3V 高 → 非反相；
   - 0V 低 → SBUS 反相，需要反相器（74HC04/三极管）或换 DR16。
3. **确认接收机型号/标签**，拍清晰照片；DT7/DR16 的 D-Bus 是 18 字节 0xA9，
   SBUS 是 25 字节 0x0F + 反相，两者不能直接混用。
4. 若确认是 SBUS：硬件加反相器，USART2 改 100000 8E2，`DBUS.c` 改成 25 字节 SBUS 解码，
   或直接换 DR16 接收机。

## 验证

当前：`status=51`、`uart2_rx=1`、`dbus_frame=0`、无 `rc_ok`。  
解决判据：`/car/status` 出现 `rc_ok`；停掉 `bridge_node` 后 `src` 变 `rc`，遥控器能驱动轮子。

## 可复用结论

- **DBUS**：18 字节/帧，帧头 `0xA9`，100000 8E1，非反相；
- **SBUS**：25 字节/帧，帧头 `0x0F`，100000 8E2，**反相**；直接接 STM32 USART 解不了；
- **PA3 有上拉**时，量 PA3 电压不能判断接收机是否反相，要量接收机信号脚；
- 串口调试先用 `uart2_rx` / `dbus_frame` 两个调试位区分“线没通”和“帧不对”，
  比盲猜快；
- CH340 在非标准波特率（100000）下可能不准，优先用 CH343/CP2102 复核。

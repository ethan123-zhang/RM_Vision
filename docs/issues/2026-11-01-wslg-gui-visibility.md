# 问题：Gazebo GUI 里“看不出 0.503 m 高台”，且 WSLg 下截图不可靠（2026-11-01）

## 现象

RMUL2027 3V3 场地在 Gazebo GUI 里看起来是“一块平面 + 上面一个小车”，看不到凸起、也看不到围栏。
模型本身没问题（`gz model --list` 有 `rmul2027_3v3_field`，日志无网格加载错误），
离屏渲染的正立面图能清楚量出 0.503 m 的墙。

## 根因（都能量化，逐条验证过）

| # | 原因 | 证据 |
|---|---|---|
| 1 | GUI 相机太高太远：旧位姿 `(-9.5,-11.5,9.0)`、俯角 26° | 12.6 m 宽场地在视口里 0.503 m 仅约 16 px |
| 2 | 地面亮度 ≈ 背景亮度 | 旧配色地面 48.1、背景 39.6（差 8） |
| 3 | **台子投影亮度 ≈ 天空亮度** | 都约 56；台子根部一圈黑 → 读成“浮在黑洞上的卡片”（主因） |
| 4 | 单一材质 + 无竖直参照物 | 整场一个灰度，除侧壁外无高度线索 |

诊断手段：把 GUI 的相机位姿/视野（`-8.5 7.5 2.6`、pitch 0.226、yaw -0.723、hfov 1.15、1000×845）
搬进离屏相机（`worlds/gui_capture_fenced.sdf`），**逐行读亮度剖面**（`probe_report.py`），
再和几何预测（`annotate_gui_view.py`）对照。最终阶梯：天空 42 / 投影地面 88 / 亮地面 95 /
侧壁 117~123 / 围栏 137 / 台面 214。

## 踩到的坑（会影响以后所有“看 GUI”的判断）

1. **`<gui><camera><track>` 会覆盖 `--gui-config` 的 `camera_pose`**。
   世界文件里留 `<track>rmul2027_3v3_field</track>` 时，`/gui/camera/pose` 回读是 6.3 m 外的环绕位姿，
   和配置里的值完全不符；删掉 `<track>` 后位姿才和配置一致。**排查 GUI 视角问题先删 track。**
2. **WSLg 下抓 GUI 画面不可靠**：X 侧 `import -window` 可能拿到冻结帧（隔 3 s 抓两张差异 0.02%）；
   Windows 侧 `CopyFromScreen` 因为 Gazebo 窗口落在副显示器 `(-2527,16)` 会抓不全。
   → 画面判断用**离屏相机**（同世界、同参数），GUI 只用 `/gui/camera/pose` 回读 + 一次实拍交叉验证。
3. **渲染图是 sRGB 编码**：线性 0.12 渲染出来是 103.7，不是 30。按线性值设亮度阈值会把整图判成“全亮”。
4. **地面平面 60×60 m 太小**：掠射光线打到平面外就露出背景色，台子根部凭空多一条“天空色暗带”。
   改成 400×400 m 才对。
5. 判断“像不像高台”别只看一处对比：要按
   `天空 < 投影地面 < 亮地面 < 侧壁 < 围栏 < 台面` 六级分开来验，任何两级撞色都会让观感退回“薄片”。

## 修复

见 `docs/decisions/2026-11-01-rm-field-fenced-gui-variant.md` 与
[`tb3_gazebo_nav2/rm_field/README.md` §10](../../../tb3_gazebo_nav2/rm_field/README.md)：
调光照/配色（只改颜色）、加补光、放大地面平面、GUI 相机换到能看到投影的一侧、删 track、
新增 0.30 m 围挡变体。改造后 GUI 实拍阶梯与离屏一致（117/137/214/90/56）。
